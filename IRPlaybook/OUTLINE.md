# IRPlaybook TH — โครงเนื้อหา (ฉบับให้ตรวจก่อนลงมือ)

คู่มือเผชิญเหตุทางไซเบอร์ภาษาไทย สำหรับหน่วยงานโครงสร้างพื้นฐานสำคัญทางสารสนเทศ

**สถานะ** ร่างโครง ยังไม่เขียนเนื้อหา
**ขอให้ตรวจ** หัวข้อครอบคลุมงานจริงไหม ขาดอะไร มีอะไรที่ไม่ควรเปิดเผยสาธารณะ

---

## หลักการออกแบบ

สามข้อนี้กำหนดทุกอย่างที่เหลือ

1. **เปิดตอนไฟไหม้ ไม่ใช่ตอนว่างอ่าน** — คนเปิดคู่มือนี้กำลังมือสั่น ทุกหน้าต้องตอบ "ตอนนี้ทำอะไรต่อ" ภายในสองวินาที ไม่ใช่เล่าทฤษฎีก่อน
2. **ออฟไลน์ได้** — เหตุจริงบางครั้งต้องตัดเน็ต หรือเครื่องที่ใช้อยู่ไว้ใจไม่ได้ ต้องเปิดจากมือถือที่ไม่ได้ต่อเน็ตได้
3. **พิมพ์ได้** — แบบฟอร์มหลักฐานต้องมีลายมือชื่อจริง ไฟล์ PDF ไม่พอ

---

## ๑ · โครงกระบวนการ

อิง NIST SP 800-61r2 (งานรัฐบาลกลางสหรัฐ ไม่มีลิขสิทธิ์) เรียบเรียงเป็นไทย

```
เตรียมพร้อม → ตรวจพบและวิเคราะห์ → ควบคุม กำจัด กู้คืน → ถอดบทเรียน
     ↑                                                        │
     └────────────────────────────────────────────────────────┘
```

หน้านี้สั้น เป็นแผนที่ให้กดเข้าไปในแต่ละช่วง ไม่ใช่บทความ

---

## ๒ · Runbook รายประเภทเหตุ ← **หัวใจของโปรเจกต์**

ทุก runbook ใช้โครงเดียวกันเป๊ะ คนเปิดจะได้ไม่ต้องเรียนรู้ใหม่ทุกครั้ง

| ส่วน | ตอบคำถามว่า |
|---|---|
| สัญญาณบ่งชี้ | รู้ได้ยังไงว่าเป็นเหตุประเภทนี้ ไม่ใช่ประเภทอื่น |
| **๖๐ นาทีแรก** | ทำอะไรก่อนหลัง เรียงเป็นข้อ กดติ๊กได้ |
| **ห้ามทำ** | สิ่งที่ทำแล้วหลักฐานหายหรือสถานการณ์แย่ลง |
| หลักฐานที่ต้องเก็บ | เรียงตามลำดับความผันผวน อะไรหายก่อน |
| การควบคุม | ระยะสั้น (หยุดเลือด) กับ ระยะยาว |
| กำจัดและกู้คืน | เงื่อนไขว่าสะอาดแล้วจริง |
| เกณฑ์ปิดเหตุ | ปิดได้เมื่อไร ใครเป็นคนตัดสิน |
| ที่มักพลาด | จากหน้างานจริง |
| เทคนิค ATT&CK | รหัส TXXXX ให้ไปตามต่อ |

### รายการ runbook ที่เสนอ

**ชุดแรก — ทำก่อน ๖ เรื่อง**

1. **Ransomware** — เจอบ่อยสุด เสียหายหนักสุด ตัดสินใจผิดในชั่วโมงแรกแล้วจบเลย
2. **เว็บหน่วยงานถูกแก้หน้า / พบ web shell** — เหตุที่หน่วยงานรัฐไทยเจอบ่อยมาก และมักรีบลบ web shell ทิ้งจนไม่เหลือหลักฐาน
3. **ข้อมูลส่วนบุคคลรั่วไหล** — มีหน้าที่ตามกฎหมายผูกอยู่ ต้องแม่น
4. **บัญชีอีเมลถูกยึด / BEC** — มักลามไปทั้งองค์กรผ่าน rule forward ที่ไม่มีใครดู
5. **Active Directory ถูกยึด** — DCSync, Golden Ticket, การกู้คืนที่ทำผิดแล้วโดนซ้ำ
6. **มัลแวร์บนเครื่องผู้ใช้** — เหตุพื้นฐานที่สุด ใช้เป็นแม่แบบให้เรื่องอื่น

**ชุดสอง — ทำตามทีหลัง**

7. DDoS
8. บุคคลภายในใช้สิทธิ์โดยมิชอบ
9. ช่องโหว่ใหม่ถูกโจมตีเป็นวงกว้าง (เช่น CVE ที่มี PoC ออกมาแล้ว)
10. เข้าถึงโดยไม่ได้รับอนุญาตผ่าน VPN / remote access

## ๓ · ชุดคำสั่งเก็บหลักฐานเบื้องต้น

ใช้หน้าตาและการทำงานแบบเดียวกับ CommandRun — เติมตัวแปรอัตโนมัติ กดคัดลอก

เรียงตาม **ลำดับความผันผวน** (RFC 3227) ของที่หายก่อนเก็บก่อน

```
รีจิสเตอร์/แคช → หน่วยความจำ → สถานะเครือข่าย → โปรเซสที่รันอยู่
→ ดิสก์ → ล็อกระยะไกล → สื่อสำรอง
```

| หมวด | ครอบคลุม |
|---|---|
| Windows — ภาพรวมระบบ | ข้อมูลเครื่อง ผู้ใช้ที่ล็อกอิน เวลาระบบ เขตเวลา |
| Windows — เครือข่าย | การเชื่อมต่อที่เปิดอยู่ ตาราง ARP DNS cache |
| Windows — โปรเซส | โปรเซสพร้อม command line โปรเซสแม่ |
| Windows — คงอยู่ในระบบ | Run keys, Scheduled Task, Service, WMI subscription |
| Windows — ล็อก | Security/System/Application, Sysmon, PowerShell |
| Windows — หน่วยความจำ | การถ่ายภาพหน่วยความจำ ข้อควรระวัง |
| Linux — ภาพรวม | เหมือนกันแต่ฝั่ง Linux |
| Linux — เครือข่าย/โปรเซส | `ss`, `lsof`, `/proc` |
| Linux — คงอยู่ในระบบ | cron, systemd, `.bashrc`, SSH key, LD_PRELOAD |
| Linux — ล็อก | `/var/log`, auditd, journald |
| อุปกรณ์เครือข่าย | ดึงล็อกจาก firewall, proxy, DNS |
| คลาวด์ | audit log ของผู้ให้บริการ |

**หมายเหตุ** คำสั่งทั้งหมดเขียนเอง ไม่ลอกจากที่ไหน (ดู `SOURCES.md`)

---

## ๔ · หลักฐานและห่วงโซ่การครอบครอง

- **แบบฟอร์มห่วงโซ่การครอบครอง** — พิมพ์ลงกระดาษ A4 เซ็นชื่อได้จริง
- **บันทึกการเข้าถึงหลักฐาน** — ใคร เมื่อไร ทำอะไร
- การคำนวณและบันทึกค่าแฮช — ทำเมื่อไร ทำยังไงให้เชื่อถือได้
- ข้อควรระวังเรื่องการรับฟังพยานหลักฐานดิจิทัล
- ป้ายติดวัตถุพยาน

> ส่วนนี้เป็นจุดที่คู่มือภาษาอังกฤษช่วยไม่ได้ เพราะแบบฟอร์มต้องเข้ากับระเบียบไทย

---

## ๕ · หน้าที่ตามกฎหมาย

**⚠️ ส่วนนี้ต้องตรวจตัวบทและประกาศฉบับปัจจุบันตอนลงเนื้อหา ห้ามเขียนจากความจำ**

- พ.ร.บ.การรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. ๒๕๖๒ — หน้าที่ของหน่วยงาน CII
- ใครต้องแจ้ง แจ้งใคร ภายในเมื่อไร ด้วยแบบฟอร์มอะไร
- PDPA — เหตุละเมิดข้อมูลส่วนบุคคล
- ผังการตัดสินใจ "เหตุนี้ต้องแจ้งไหม"
- เทมเพลตหนังสือแจ้งเหตุ

ข่าวดี — ตาม พ.ร.บ.ลิขสิทธิ์ มาตรา ๗ **ตัวบทกฎหมายและประกาศราชการไม่มีลิขสิทธิ์**
ยกมาอ้างได้เต็มที่ ไม่ต้องขออนุญาตใคร

---

## ๖ · เครื่องมือในหน้า ทำงานในเบราว์เซอร์ล้วน

| เครื่องมือ | ทำอะไร |
|---|---|
| **ตัวสร้างไทม์ไลน์** | วางเหตุการณ์ เรียงตามเวลา ส่งออก CSV / Markdown / JSON |
| ตัวประเมินระดับความรุนแรง | ตอบคำถามไม่กี่ข้อ ได้ระดับความรุนแรงพร้อมเหตุผล |
| ตัวแปลงเวลา | UTC ↔ ICT และ epoch — ล็อกส่วนใหญ่เป็น UTC คนอ่านคิดเป็นไทย ตรงนี้พลาดกันบ่อย |
| เช็กลิสต์เก็บหลักฐาน | ติ๊กตามไป จำสถานะไว้ ส่งออกเป็นบันทึกได้ |

ทั้งหมดไม่ส่งข้อมูลออกจากเครื่อง — สำคัญมาก เพราะคนใช้กำลังพิมพ์ข้อมูลเหตุจริงลงไป

---

## ๗ · ภาคผนวก

- คำศัพท์ไทย–อังกฤษ (containment แปลว่าอะไรให้ผู้บริหารเข้าใจ)
- ผังการตัดสินใจ: เมื่อไรควรตัดเครือข่าย เมื่อไรไม่ควร
- รายชื่อหน่วยงานที่ต้องประสาน
- แหล่งอ้างอิงที่ใช้ พร้อมสัญญาอนุญาต

---

## สิ่งที่ **ไม่** อยู่ในโปรเจกต์นี้

เขียนไว้ให้ชัดตั้งแต่ต้น กันหลงทางทีหลัง

- ❌ ขั้นตอนปฏิบัติภายในของหน่วยงาน เบอร์ติดต่อจริง ชื่อระบบจริง
- ❌ ตัวอย่างเหตุจริงที่ระบุตัวหน่วยงานได้
- ❌ เครื่องมือโจมตี — อันนั้นเป็นงานของ CommandRun
- ❌ คำแนะนำทางกฎหมาย — บอกได้แค่ว่ากฎหมายเขียนว่าอะไร ไม่ใช่ว่าควรทำอะไร

---

## ที่อยากให้ตรวจเป็นพิเศษ

1. runbook ชุดแรก ๖ เรื่อง ตรงกับที่เจอจริงไหม ควรสลับลำดับไหม
2. แบบฟอร์มห่วงโซ่การครอบครอง ควรอิงแบบของหน่วยงานไหนเป็นต้นแบบ
3. ส่วนกฎหมาย — มีประกาศ กมช./สกมช. ฉบับไหนที่ต้องอ้างบ้าง
4. มีอะไรในนี้ที่เปิดเผยสาธารณะแล้วจะมีปัญหากับระเบียบราชการไหม

เรื่องที่ ๔ โมกะตัดสินใจแทนไม่ได้ ต้องนายท่านดูเอง
